## How the user wants the work done
- **Keep going until the project is end-to-end submission-ready.** The user's words: "pass
  should only end when there is an end to end submission ready project, until then, tests
  or retries or checks need to be conducted and verified by you or an adversarial agent".
- For each stage: **do → independent adversarial review → fix → re-review**, until a review
  round finds no blocker or major issues. Reviewers must give evidence: a command they ran,
  a line of code or a number they recomputed. The final gate needs **2 consecutive clean
  rounds** across reproducibility, rubric coverage, numbers and honesty, and readability.
  Then spot-check the work yourself.
- The user asked for Workflow-based orchestration (multi-agent) in the earlier session.
  `docs/handoff/workflow_windows_reference.js` is the script that was running. It has
  Windows paths, so adapt it before reuse. Its prompts for Steps 4–6 and the final gate
  are the detailed spec for the remaining work.
- A failed or empty agent or review must never count as a pass.

## Ground rules (from the brief, non-negotiable)
- `SEED = 42` everywhere.
- Never select, tune or early-stop on `test_random` or `test_future`. They are for final
  scoring only.
- Every table and figure is generated by a script from `reports/experiments.jsonl` or from
  saved artefacts. Never type numbers by hand.
- Report negative or surprising results honestly. A large drift gap, or an AutoML tool
  falling for the leak, is a finding to report, not a bug to fix.
- Code must stay readable for a student team: small typed functions, short "why" comments,
  matching the existing style.
- Never run Python with `data/raw` as the working directory or on `sys.path`. It holds
  untrusted downloaded data.
- Long jobs (more than 2 minutes) run as detached background processes that write a log
  file. Poll the log with short checks; a shell call's timeout must not kill a run. Timed
  AutoML runs need the machine to themselves, so never run two at once.
- If you add a dependency, pin it in `requirements.txt`.
- Quick smoke runs use `EMBER_QUICK=1` (or `run_all.py --quick`) and write `*_quick` files.
  They never overwrite real results.
